# Candidate agent workloads for JouleServe-WS and the later edge work

**Provenance legend.** [paper] = seen in the cited paper via arXiv HTML/abstract (through a fetch summarizer, so re-check before citing). [background] = my prior knowledge of the benchmark, NOT re-verified in this pass (licenses, sizes). [inferred] = my estimate. Nothing here was run.

**Key framing.** Retained state matters only if (a) each turn appends to one accumulating context (native tool-calling / ReAct message history, not rebuilt role prompts) AND (b) the tool wait is long relative to recompute cost AND (c) there are several concurrent sessions. Most public benchmarks have tool waits of ms to ~2 s (real tools) or zero (replay/simulated). Only drone/robot simulators and real sandboxes give multi-second waits. Any of them can be paired with **injected waits drawn from P1's measured distributions** (median 13 / 37 / 115 s, up to 15 min) [inferred design option].

## Notes
- **Waits are the scarce ingredient.** Measured real waits: SWE/coding sandboxes ~1 s mean with heavy tails (Continuum); BFCL web search ~1.9 s; TokenCake MCP profile 0.1 ms-30 s; production idle 1-10 min (AgentSysBench, human/approval-heavy); P1 drone 13-115 s. Standard benchmarks with mock tools (BFCL, tau, ALFWorld, ToolBench cache) have ms waits, so they need injected waits.
- **Context vs KV pool.** WS KV pool is ~25K tokens on one GPU. Continuum's 70-93K-token programs do not fit; ALFWorld, tau, MultiUAV-Plat, TokenCake (1-5K) do.
- **Hybrid models** change what "state" is; none of these workloads are model-dependent.

## Ranked shortlist for JouleServe-WS
1. **MultiUAV-Plat** — drone/edge-plausible (matches P1's story), sessions of ~20 sequential tasks with state carried across, tool-like REST APIs, code GPL-3.0 (paper CC BY 4.0), lightweight Python sim (no Docker stated). Gap: waits unspecified/probably short, LLM tested via API only; add injected or simulator-scaled waits and verify accumulation within a session.
2. **tau²-bench (or tau-bench)** — real native tool-calling with long accumulating dialogues, natural N-parallel conversations, MIT, local via OpenAI-compatible endpoints; conversation turns supply human-like gaps. Tool waits themselves are ms, so inject waits. Low setup risk (pip); needs a user-sim model (can be a second small model on GPU 1).
3. **ALFWorld** — embodied household robot, pure-text pip install, accumulating ReAct history of ~20-50 steps that fits the 25K KV pool, trivially concurrent. Waits must be injected (simulator is instant).
4. **SimuHome / SMH-Bench** — smart-home agents with time-accelerated simulation where scheduled devices create genuine waiting semantics; edge-plausible. Risk: code release unconfirmed; check before committing.
5. **MLPerf Edge Agentic replay + BFCL multi-turn** — standardized, citable, Thor-native; use as a "prefill-heavy, standardized" second regime and as an edge validation workload. Concurrency=1 and no waits by rule, so wrap in our own multi-session driver.
Fallback if none shows retention benefit: Continuum's SWE/BFCL traces (long contexts, real waits) as a cloud-comparison cross-check, not primary. Avoid WebArena/OSWorld/AgentBench (Docker/VMs, not edge-plausible).
